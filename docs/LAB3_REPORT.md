## ВСТУП ТА МЕТА РОБОТИ

**Мета роботи:** Спроєктувати та практично імплементувати масштабований модульний каркас веб-застосунку «MKV Racing» для серверної інфраструктури автосимулятора Assetto Corsa на базі сучасної бібліотеки React 18 та збирача Vite. Відповідно до обов'язкових вимог технічного завдання інтегрувати комплекс інструментів забезпечення якості та надійності вихідного коду: налаштувати статичний аналізатор ESLint 9 з підтримкою хуків React, конфігурувати інструмент автоматизованого форматування Prettier, розгорнути механізм перехоплювачів Git Hooks на базі Husky v9 та lint-staged для автоматичного контролю цілісності коду перед створенням комітів та пушів у віддалений репозиторій. Розробити матрицю тестування із застосуванням рекомендованого фреймворку Cypress, що включає як компонентні (юніт) тести ізольованих інтерфейсних блоків, так і наскрізні (End-to-End) тести користувацьких сценаріїв навігації та авторизації. Обґрунтувати архітектурне рішення декомпозиції коду, опублікувати структурні зміни у відкритому GitHub-репозиторії та відкрити Pull Request із підключенням академічних рецензентів.

## РОЗДІЛ 1. ДЕТАЛЬНИЙ ОПИС ІДЕЇ ВЕБ-ЗАСТОСУНКУ ТА ВІДПОВІДНІСТЬ СТРУКТУРИ ПРОЄКТУ БІЗНЕС-ДОМЕНУ

### 1.1. Доменна модель проєкту «MKV Racing» та системні вимоги до кодової бази

Веб-платформа «MKV Racing» розробляється як спеціалізований хаб моніторингу, телеметрії та швидкого підключення до багатокористувацьких серверів автосимулятора Assetto Corsa (локації Shuto Revival Project у Токіо та AC Georgia у Тбілісі). На відміну від звичайних веб-сайтів-візиток, даний застосунок оперує високонавантаженими потоками даних у реальному часі: кожні 25 мілісекунд (частота 40 Hz) клієнт отримує телеметричні пакети CSP (Custom Shaders Patch), координати болідів на міні-радарі, швидкість потоку AI-трафіку та зміни стану погодного рушія Pure 3.10.

Вимоги до високої швидкодії та паралельної обробки даних вимагають чіткого розмежування зон відповідальності в кодовій базі. Файлова структура проєкту безпосередньо відображає доменні сутності платформи:
- **Домен серверного кластера (`/src/features/servers/`):** інкапсулює логіку фільтрації ігрових нод, обробку мережевих бабблів (300 метрів), розрахунок завантаженості слотів (до 170 слотів) та виклик браузерного протоколу `acmanager://` для одноклікового запуску гри.
- **Домен віртуального гаража (`/src/features/garage/`):** відповідає за виставковий 3D WebGL-бокс болідів (Toyota Supra MKV, Audi R8 V10, Porsche 911 GT3 RS, BMW M5 CS), конфігурацію кольорів ліврей та криптографічну перевірку хеш-сум модів за стандартом SHA-256.
- **Домен телеметрії та сесій (`/src/features/statistics/`):** забезпечує рендеринг графіків бічного прискорення (Lateral G), секторного таймінгу петлі Shuto C1 та розрахунку водійського індексу надійності.
- **Домен авторизації та профілю пілота (`/src/features/auth/`, `/src/features/profile/`):** реалізує безшовну інтеграцію через Steam OpenID 2.0 SSO для перевірки ліцензійних DLC автосимулятора та збереження кар'єрного прогресу рівня Level 42 Pro Tier.
- **Домен системної діагностики (`/src/features/logs/`):** забезпечує прийом консольного стріму логів ядра AssettoServer через постійне WebSocket-з'єднання з фільтрацією подій Info, Warn та Checksum Pass.

## РОЗДІЛ 2. ПРЕДСТАВЛЕННЯ СТРУКТУРИ ПРОЄКТУ ТА ОБҐРУНТУВАННЯ АРХІТЕКТУРИ

### 2.1. Представлення структури директорій та файлів репозиторію

У проєкті впроваджено модульну доменно-орієнтовану структуру (Feature-Based Modular Architecture), адаптовану під стандарти React 18 та збирача Vite. Повна ієрархія файлової системи має наступний вигляд:

```text
mkv-racing-web/
├── .husky/                         # Перехоплювачі Git Hooks
│   ├── pre-commit                  # Скрипт запуску lint-staged перед створенням коміту
│   └── pre-push                    # Скрипт валідації лінтером перед відправкою у віддалену гілку
├── cypress/                        # Автоматизовані тести на базі фреймворку Cypress
│   ├── component/                  # Компонентні (юніт) тести ізольованих React-компонентів
│   │   ├── AuthModal.cy.jsx        # Тест валідації форми та передачі облікових даних
│   │   └── ServerCard.cy.jsx       # Тест монтування картки сервера та виклику протоколу acmanager://
│   ├── e2e/                        # Наскрізні End-to-End тести користувацьких сценаріїв
│   │   ├── auth.cy.js              # E2E-тест модального вікна авторизації та Steam SSO
│   │   └── navigation.cy.js        # E2E-тест перемикання маршрутів без перезавантаження сторінки
│   ├── fixtures/                   # Тестові мокові набори даних
│   │   └── servers.json            # Фікстури телеметрії серверних кластерів
│   └── support/                    # Допоміжні команди та налаштування оточення Cypress
│       ├── commands.js             # Кастомні команди (cy.loginPilot)
│       ├── component.js            # Монтування компонентів із глобальними стилями Tailwind
│       └── e2e.js                  # Глобальний хук життєвого циклу тестів
├── public/                         # Статичні нескомпільовані файли та фавікони
├── src/                            # Вихідний програмний код веб-застосунку на React
│   ├── components/                 # Спільні універсальні компоненти (UI Kit & Layout)
│   │   ├── common/                 # Атомарні компоненти інтерфейсу
│   │   │   ├── Badge.jsx           # Індикатор онлайн-статусу та рівнів надійності
│   │   │   ├── Button.jsx          # Багатофункціональна кнопка (Primary, Secondary, Steam)
│   │   │   ├── Input.jsx           # Текстові поля вводу з валідацією помилок
│   │   │   └── Modal.jsx           # Універсальне модальне вікно на базі React Portals
│   │   └── layout/                 # Каркасні компоненти сторінки
│   │       ├── Footer.jsx          # Підвал сторінки зі системними версіями
│   │       └── Navbar.jsx          # Фіксована панель навігації та перемикач вкладок
│   ├── features/                   # Ізольовані функціональні модулі (Feature Slices)
│   │   ├── auth/                   # Модуль автентифікації (AuthModal.jsx, Steam SSO)
│   │   ├── dashboard/              # Головний екран моніторингу (DashboardPage.jsx, ServerCard.jsx)
│   │   ├── garage/                 # Віртуальний 3D-гараж та селектор ліврей (GaragePage.jsx)
│   │   ├── logs/                   # Консольний термінал системних логів (LogsPage.jsx)
│   │   ├── profile/                # Особистий кабінет пілота та пробіг автопарку (ProfilePage.jsx)
│   │   ├── servers/                # Інфраструктура кластера та параметри нод (ServersPage.jsx)

│   ├── store/                      # Централізоване сховище глобального стану (Zustand)

│   └── main.jsx                    # Точка монтування React-дерева в DOM
├── .eslintrc.cjs                   # Конфігурація лінтера ESLint у форматі CommonJS
├── .gitignore                      # Перелік виключень системи контролю версій Git
├── .prettierignore                 # Файли, що ігноруються автоматичним форматуванням
├── .prettierrc                     # Конфігурація правил форматування Prettier

├── index.html                      # Головний HTML5-шаблон із метаданими та шрифтами
├── package.json                    # Маніфест залежностей проєкту, скриптів та lint-staged
├── tailwind.config.js              # Конфігурація токенів кольорів та типографіки Tailwind
└── vite.config.js                  # Конфігурація збирача Vite та плагіна React
```

### 2.2. Порівняльний аналіз архітектурних рішень

| Критерій оцінки | Пласка структура (Type-Based / Flat) | Модульна структура (Feature-Based / MKV Racing) |
| :--- | :--- | :--- |
| **Організація файлів** | Розділення за технічним типом: всі компоненти в одній директорії. | Групування за бізнес-доменами: фіча містить свій UI, логіку та стилі. |
| **Зв'язність коду (Coupling)** | Висока зв'язність; зміни в одному файлі можуть зачепити сторонні екрани. | Слабка зв'язність (Loose Coupling); фічі повністю ізольовані одна від одної. |
| **Масштабованість (Scalability)** | При зростанні кількості файлів понад 25 папка перетворюється на звалище. | Висока масштабованість; додавання нової локації чи сторінки не чіпає існуючий код. |
| **Зручність тестування** | Тести розпорошені або знаходяться окремо, важко відслідкувати покриття. | Компонентні тести Cypress знаходяться у прямому зв'язку з конкретною фічею. |
| **Швидкість навігації розробника** | Низька: доводиться постійно перемикатися між 5 віддаленими папками. | Висока: весь контекст задачі зосереджений усередині відповідної фічі. |
