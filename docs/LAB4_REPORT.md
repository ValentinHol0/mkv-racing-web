## ВСТУП ТА МЕТА РОБОТИ

**Мета роботи:** Спроєктувати та реалізувати повноцінний інтерфейс користувача веб-застосунку «MKV Racing» на базі сучасної бібліотеки React 18 із суворим дотриманням обов'язкової академічної вимоги щодо повної відмови від використання сторонніх CSS-фреймворків (Tailwind CSS, Bootstrap, Materialize, UIKit тощо). Імплементувати модульний компонентний підхід до стилізації вихідного коду за допомогою технології CSS Modules (`*.module.css`) та дворівневої системи глобальних токенів дизайну (CSS Custom Properties). Створити необхідний мінімум функціональних сторінок (Dashboard, Servers, Garage, Telemetry, Pilot Profile, Console Logs) та модульне вікно автентифікації пілотів AuthModal (без перевантаження складною бізнес-логікою). Забезпечити повну адаптивність, естетику автоспортивного інтерфейсу Dark Racing UI, провести автоматизоване тестування розроблених компонентів та опублікувати структурні зміни у вигляді Pull Request на платформі GitHub.

## РОЗДІЛ 1. ДЕТАЛЬНИЙ ОПИС ІНТЕРФЕЙСУ ТА КОМПОНЕНТНОЇ МОДЕЛІ ПРОЄКТУ

### 1.1. Декомпозиція веб-застосунку та представлені сторінки (Views)

Відповідно до індивідуального технічного завдання розроблювана веб-платформа «MKV Racing» призначена для віддаленого моніторингу, збору телеметрії та швидкого підключення до багатокористувацьких серверів автосимулятора Assetto Corsa. У лабораторній роботі №4 реалізовано необхідний і розширений набір екранних форм (6 повноцінних сторінок та модальне вікно авторизації):
1. **Головна панель моніторингу (`DashboardPage`)** — центральний екран оператора, що відображає інтерактивні картки серверів із завантаженістю слотів, динамічний погодний віджет Pure 3.10 Rain Engine, живий радар мережевого баббла (радіус 300 метрів) та поточний рейтинг пілотів на петлі Shuto Expressway C1.
2. **Серверна інфраструктура (`ServersPage`)** — каталог кластерів автосимулятора з фільтрацією за географічними локаціями (Japan SRP / Georgia Tbilisi), характеристиками мережевого оновлення (40 Hz / 30 Hz) та інструкцією виклику браузерного протоколу `acmanager://`.
3. **Віртуальний 3D-гараж (`GaragePage`)** — інтерактивний бокс вибору болідів (Toyota Supra MKV, Audi R8 V10, Porsche 911 GT3 RS, BMW M5 CS), панель вибору фірмових ліврей та таблиця детальних інженерних характеристик (потужність, крутний момент, розгін 0-100 км/год, привід).
4. **Аналітика та телеметрія (`StatisticsPage`)** — екран візуалізації динамічних показників: бічного прискорення (Lateral G), секторного таймінгу петлі Shuto C1 та розрахункового водійського індексу безпеки.
5. **Особистий кабінет пілота (`ProfilePage`)** — статус кар'єри Driver Level 42 Pro Tier, перевірка ліцензійних Kunos DLC за стандартом Steam OpenID 2.0 та журнал сукупного пробігу автопарку пілота.
6. **Консоль системних логів (`LogsPage`)** — повноцінний емулятор термінала ядра AssettoServer UDP/TCP 9601 із можливістю фільтрації подій рівнів Info, Warn, Checksum Pass та введення оперативних команд.
7. **Модуль авторизації (`AuthModal`)** — універсальне модальне вікно для швидкого входу пілота через Steam OpenID 2.0 SSO або введення облікового токена.

### 1.2. Графічне представлення інтерфейсу користувача (Screenshots)

Для наочної демонстрації розроблених сторінок та компонентів виконано автоматизоване захоплення екранів інтерфейсу:
- **Рис. 1.1.** Інтерфейс головної панелі моніторингу (`DashboardPage`) на базі чистих CSS Modules.
- **Рис. 1.2.** Модальне вікно швидкої автентифікації пілотів (`AuthModal`) через Steam OpenID 2.0 SSO.
- **Рис. 1.3.** Каталог серверних кластерів Assetto Corsa (`ServersPage`).
- **Рис. 1.4.** Віртуальний 3D-гараж вибору болідів та інженерних характеристик (`GaragePage`).
- **Рис. 1.5.** Аналітика телеметрії та секторного таймінгу петлі Shuto C1 (`StatisticsPage`).
- **Рис. 1.6.** Особистий кабінет пілота з верифікованими ліцензіями Steam DLC (`ProfilePage`).
- **Рис. 1.7.** Консоль термінала серверного ядра UDP/TCP (`LogsPage`).

### 1.3. Багаторівнева компонентна ієрархія (UI Kit та Layout)

Для забезпечення принципу DRY (Don't Repeat Yourself) та високої масштабованості компонентна структура розділена на три взаємодіючі рівні:
- **Атомарні базові компоненти (UI Kit):** `Badge` (індикатор онлайн-статусу, рівнів надійності та бейджів з пульсуючою анімацією), `Button` (багатофункціональна кнопка з варіантами Primary, Secondary, Steam OpenID, Outline та різними розмірами), `Input` (текстові поля введення з підтримкою іконок та валідацією помилок), `Modal` (модальне вікно на базі React Portals із блокуванням прокрутки).
- **Каркасні компоненти (Layout):** `Navbar` (фіксована навігаційна шапка з адаптивним меню та панеллю пілота), `Footer` (підвал сторінки з технічними специфікаціями та інформацією про версії протоколів).
- **Доменні компоненти (Feature Slices):** `ServerCard`, `DashboardPage`, `ServersPage`, `GaragePage`, `StatisticsPage`, `ProfilePage`, `LogsPage`, `AuthModal`.

## РОЗДІЛ 2. АРХІТЕКТУРА СТИЛІЗАЦІЇ З ВИКОРИСТАННЯМ CSS MODULES (БЕЗ CSS-ФРЕЙМВОРКІВ)

### 2.1. Обґрунтування відмови від сторонніх CSS-фреймворків

Відповідно до академічних вимог дисципліни, використання утилітарних бібліотек на зразок Tailwind CSS, Bootstrap чи UIKit було повністю виключено з кодової бази. Утилітарні фреймворки генерують велику кількість сторонніх залежностей, засмічують JSX-розмітку довгими рядками несемантичних класів та обмежують гнучкість тонкого налаштування складних станів інтерфейсу.

Натомість, обрана технологія CSS Modules володіє фундаментальними перевагами:
1. **Нульовий оверхед залежностей:** CSS Modules підтримуються збирачем Vite нативно без встановлення додаткових бібліотек.
2. **Локальна область видимості (Scoped CSS):** Класи автоматично хешуються (наприклад, `ServerCard_card__a1b2c`), що виключає колізії селекторів.
3. **Семантична чистота розмітки:** У JSX використовуються зрозумілі модульні селектори (`styles.card`, `styles.loadBar`).
4. **Прямий доступ до нативних можливостей браузера:** Підтримка CSS Grid, Flexbox, анімацій `@keyframes` та змінних `var(--token)`.

### 2.2. Система глобальних дизайн-токенів (`variables.css`)

Для забезпечення цілісності дизайну створено централізований файл `src/styles/variables.css`, який визначає систему CSS-змінних:

## РОЗДІЛ 3. РЕАЛІЗАЦІЯ МОДУЛЬНИХ ТАБЛИЦЬ СТИЛІВ ДЛЯ КОМПОНЕНТІВ

У кожному функціональному каталозі проєкту створено ізольований файл стилів, що підключається безпосередньо у відповідний JSX-компонент:
- `src/components/common/Badge.module.css` — стилізація бейджів різних станів;
- `src/components/common/Button.module.css` — дизайн кнопок з варіантами Primary, Secondary, Steam OpenID;
- `src/components/common/Input.module.css` — поля введення з плаваючими межами та станами фокусу;
- `src/components/common/Modal.module.css` — оверлей з ефектом `backdrop-filter: blur(4px)`;
- `src/components/layout/Navbar.module.css` — фіксований хедер із напівпрозорим фоном;
- `src/components/layout/Footer.module.css` — адаптивний підвал із відображенням параметрів 40 Hz;
- `src/features/dashboard/ServerCard.module.css` — картка сервера з динамічним індикатором завантаження;
- `src/features/dashboard/DashboardPage.module.css` — верстка дашборду через CSS Grid;
- `src/features/garage/GaragePage.module.css` — сцена віртуального боксу із сіткою підлоги;
- `src/features/statistics/StatisticsPage.module.css` — шкали бічного перевантаження та секторні спліти;
- `src/features/profile/ProfilePage.module.css` — плашка пілота, список DLC-паків Steam OpenID;
- `src/features/logs/LogsPage.module.css` — термінал з емуляцією вікна macOS;
- `src/features/auth/AuthModal.module.css` — форма авторизації з роздільником та кнопкою швидкого входу Steam.
